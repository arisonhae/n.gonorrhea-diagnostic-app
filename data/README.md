# 데이터셋

원본 이미지는 용량 문제로 이 저장소에 포함하지 않았습니다.
`samples/` 폴더에 각 유형별 예시 이미지 몇 장만 넣어 두었습니다.

전체 데이터셋: **(여기에 Zenodo / Google Drive 링크를 넣으세요)**

---

## 촬영 조건

| 항목 | 값 |
|---|---|
| 조명 | 청색 LED transilluminator |
| 필터 | 앰버 필터 |
| 거리 | 약 10–15 cm |
| 기기 | (촬영에 사용한 스마트폰 기종을 적으세요) |

한 장의 사진에 튜브 두 개를 세로로 배치해 촬영합니다.
**위쪽이 음성 대조군(NC), 아래쪽이 검사 시료**입니다.
이 배치는 판정 로직의 전제이므로 반드시 지켜야 합니다.

---

## 폴더 구조

```
data/
├── samples/                  저장소에 포함된 예시 이미지
│
├── solo/                     튜브 1개 이미지 (절댓값 분석용)
│   ├── train/
│   │   ├── neg/
│   │   └── pos/
│   └── test/
│       ├── neg/
│       └── pos/
│
├── pair/                     튜브 2개 이미지 (비율 분석용)
│   ├── neg_pos/                위=NC, 아래=양성 시료
│   └── neg_neg/                위=NC, 아래=음성 시료 (위양성 확인용)
│
└── qc_test/                  촬영 품질 이상 이미지
    ├── error_splash/           용액이 튀어 ROI가 흩어진 경우
    ├── error_blur/             초점이 맞지 않은 경우
    └── error_light/            빛반사가 심한 경우
```

`solo` 는 형광 절댓값의 분포를 보기 위한 것이고,
`pair` 는 NC 대비 비율을 계산하기 위한 것입니다.
`qc_test` 는 검출 실패 상황에서 시스템이 오판하지 않고
"판정 불가"로 빠지는지 확인하는 데 사용했습니다.

---

## 라벨 규칙

- `solo` 이미지의 라벨은 **폴더명**(`pos` / `neg`)에서 가져옵니다.
- `pair` 이미지는 **위치**로 역할이 정해집니다. 위 = NC, 아래 = 시료.
  파일 안에 라벨 정보가 없으므로, 촬영 시 순서를 지키는 것이 중요합니다.

## YOLO 학습 데이터

튜브·ROI 검출 모델 학습에는 Roboflow 로 관리한 별도 데이터셋을 사용했습니다.

- 클래스: `tube`, `roi` (2개)
- 어노테이션: bounding box
- 분할: train / valid / test

주의: 이 분할은 **이미지 단위**로 이루어졌습니다. 같은 튜브를 여러 각도로
촬영한 이미지가 서로 다른 split 에 들어갔을 가능성이 있으며,
이 경우 검출 성능이 실제보다 높게 평가됩니다. 자세한 내용은 최상위
README 의 한계 섹션을 참고하세요.
